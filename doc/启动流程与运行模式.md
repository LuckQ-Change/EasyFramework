# 自定义流程、运行环境与场景

## 安装向导

打开入口场景，进入 `Tools > EasyFramework > Setup Wizard`，选择场景和 `Assets` 内的输出目录。

| 起点 | 写入和绑定 |
| --- | --- |
| 最小本地 | 创建 Startup Config，以离线模式启动模块宿主和 SceneModule。 |
| 标准 UI | 创建 Startup Config、页面清单和别名为 `main` 的直接引用包，启用默认模块、场景和 UI。 |
| 在线更新 | 创建 Startup Config 和页面清单，关联已有的资源包、随包发行、Player 基线和可选渠道。预览校验这些配置并报告当前构建平台及脚本后端。 |

点「预览改动」核对项目资产路径与 Launcher 绑定，再点「应用配置」。如果所选场景已有默认 Launcher 和启动配置，可以点「定位启动配置」。场景绑定支持一次 Undo，生成的资产可继续使用。保存入口场景，在构建时将它加入 Build Settings。

标准 UI 安装后点「创建页面」。页面创建器自动选中启动配置的页面清单和 `main` 直接引用包，生成页面时同时登记清单、包内地址和 Prefab 引用。在线更新准备步骤见 [热更配置](模块职责/Hotfix.md)。

## 设计边界

框架只提供 `ProcedureBase`、`ProcedureContext` 和 `ProcedureModule`，不再内置 Startup、Resource、HotUpdate、Preload、Login、Game、Exit 等具体业务流程。

具体流程必须写在项目程序集里。这样流程可以直接引用项目自己创建的 `LoginView`、角色脚本、服务和配置，不会受到“框架程序集不能反向引用项目程序集”的限制。

## 定义项目流程

项目可以继承 `ProcedureContext` 保存一条流程共享的业务状态：

```csharp
public sealed class GameProcedureContext : ProcedureContext
{
    public LoginView LoginView { get; set; }
    public PlayerService PlayerService { get; }

    public GameProcedureContext(PlayerService playerService)
    {
        PlayerService = playerService;
    }

    protected override void OnDispose()
    {
        if (LoginView != null)
            _ = LoginView.CloseAsync();
    }
}
```

具体流程同样放在项目程序集里，因此可以直接使用项目类型：

```csharp
public sealed class LoginProcedure : ProcedureBase
{
    protected override async Task<Type> OnEnterAsync(CancellationToken cancellationToken)
    {
        GameProcedureContext context = RequireContext<GameProcedureContext>();
        context.LoginView = await LoginView.OpenAsync(token: cancellationToken);
        cancellationToken.ThrowIfCancellationRequested();
        return Stay();
    }

    protected override async Task OnExitAsync(CancellationToken cancellationToken)
    {
        GameProcedureContext context = RequireContext<GameProcedureContext>();
        if (context.LoginView != null)
            await context.LoginView.CloseAsync();
        context.LoginView = null;
    }
}
```

返回 `Next<TProcedure>()` 会进入已登记的下一流程。返回 `Stay()` 会停留，等待项目代码调用 `ChangeAsync<TProcedure>()`。`StartAsync`、`ChangeAsync` 和 `Next` 的目标都要在当前宿主中登记。

切换期间暂停流程的 Tick。调用方可通过 `IsTransitioning` 禁用重复触发，忙碌期间的额外切换会立即报错。无需自定义上下文时可直接调用 `StartAsync<TProcedure>()`。

项目可以登记工厂或已有的流程实例。工厂在首次使用时执行，构造参数由项目提供。

## 显式装配与宿主选择

在启动配置的「模块装配」中选择内置模块，并将项目的 `FrameworkModuleInstaller` 资产加入装配器列表。使用 `Add<T>(typeof(TDependency))` 声明必须先就绪的依赖。需要构造参数时，可传入接收宿主的工厂，通过 `host.Require<T>()` 获取已就绪的依赖。

```csharp
[CreateAssetMenu(menuName = "Game/Module Installer")]
public sealed class GameModuleInstaller : FrameworkModuleInstaller
{
    public override void Configure(ModuleComposition composition)
    {
        composition.Add<NetworkModule>(_ => new NetworkModule(new TcpNetClient()));
        composition.Add<SaveModule>(typeof(AssetModule));
    }
}
```

示例中的 `SaveModule` 是项目模块，要求同一份配置提供 `AssetModule`，例如配置资源包。若同一类型由多个装配器登记，框架会报告重复声明。

需要流程时，把自己实现的 `FrameworkModuleInstaller` 资产放入「模块安装器」。在装配器的 `Configure` 方法中为各流程登记工厂。

```csharp
composition.Add<ProcedureModule>(_ =>
{
    var procedures = new ProcedureModule();
    procedures.Register(() => new LoginProcedure());
    procedures.Register(() => new GameProcedure());
    return procedures;
});
```

接受基础 `ProcedureContext` 的流程可以在装配器中通过 `ConfigureStartup<T>()` 设为自动首流程，启动管线会在宿主就绪后进入它。需要自定义上下文时，在项目入口手动启动已经登记的流程。

```csharp
private async void Start()
{
    await _launcher.Ready;
    var context = new GameProcedureContext(new PlayerService());
    await _launcher.Modules.Require<ProcedureModule>().StartAsync<LoginProcedure>(context);
}
```

场景中的 Launcher 可选 `Default` 或 `Isolated`。同时最多有一个默认宿主，由它提供默认模块作用域、全局 UI 和 OnGUI Debug。多个隔离宿主可以同时存在，分别绑定启动配置、模块实例和运行模式，随各自 Launcher 停止。需要等待关闭时，调用 `await launcher.StopAsync()`。

代码创建会话时，在 Launcher 上关闭「自动启动」，启用组件后调用 `launcher.StartAsync(config, FrameworkHostMode.Isolated, composition => ...)`。场景自动启动时，直接在 Launcher 引用 Startup Config。

## 启动配置

`FrameworkStartupConfig` 负责框架级运行环境、显示基础设施和模块装配。主要配置包括：

- 内置模块与项目模块装配器。
- 场景模块开关，默认启用。
- Runtime Mode。
- 资源包列表、启动常驻资源与可选的空闲缓存预算。
- 是否启动 UI、渲染模式、相机、EventSystem 和 UI Layer。
- UI 的参考分辨率和宽高匹配值。
- UI 共享背景。

首流程可以等待 `launcher.StartupAssetsReady`。常驻资源加载失败后，就绪任务会等重试成功。停止宿主时会先取消尚未完成的就绪任务，再等待首流程和模块收尾。

## 运行环境

每个宿主在模块初始化前保存自己的 Runtime Mode。`launcher.Modules.RuntimeMode` 和 `Host.RuntimeMode` 可显式读取该宿主的值。旧 `Runtime.Mode` 优先读取当前作用域，作用域外读取默认宿主。

- Editor：编辑器开发环境。
- Online：在线运行环境。
- Offline：本地或单机运行环境。
- Web：Web 运行环境。

### 单机离线构建

在 `FrameworkStartupConfig` 将运行模式设为 `Offline`，清空 `Hot Update Channel`。如需随包运行 HybridCLR，仍可绑定本地发行。纯内置资源包只需随 Player 打包。

使用 YooAsset 时，先按 Player 的构建目标构建资源包，将内置文件复制到 StreamingAssets。在 YooAsset 构建窗口可以选 `ClearAndCopyAll` 生成完整的内置包。在启动配置的 Inspector 点「校验离线配置」，可检查内置版本文件、清单、Catalog、页面和常驻资源以及随包发行声明的 Bundle 依赖。Player 构建会对本次场景引用的离线启动配置执行同一校验。WebGL 使用独立的文件系统，跳过原生内置包检查。

资源包可通过 Startup Config 登记。纯代码配置可以在没有内置资源模块声明时，通过自己的装配器添加该模块。

```csharp
public override void Configure(ModuleComposition composition)
{
    composition.Add<AssetModule>(host =>
    {
        var assets = new AssetModule();
        assets.RegisterPackage(AssetModule.MainPackage, () => CreateLoader(host.RuntimeMode));
        return assets;
    });
}
```

## 可选运行时诊断

在 `FrameworkStartupConfig` 的「可选运行时诊断」中，将 `OnGUI Debug` 设为「开发构建」。由 `FrameworkLauncher` 启动后，在 Game 视图点击 FPS 徽标或按 `F8`，可查看启动状态、日志、性能、活跃资源租约和 UI 状态。徽标可拖到安全区内，收起后继续保留最近日志。

诊断程序集 `com.wjq.easyframework.diagnostics` 只参与编辑器和 `Development Build`，普通 Player 的编译不包含这个程序集。项目可以独立移除诊断目录，框架启动器只提供通用的配置就绪通知。新建配置默认关闭。

启动页显示本地宿主、常驻资源、热更发行来源、阶段、回退原因和重试状态。日志页保留最近 500 条，支持级别过滤、搜索和查看堆栈。启动、性能、资源和 UI 页只在对应页可见时采样，最高 5 Hz。资源页区分活跃租约和空闲缓存，UI 页显示托管页面和状态控制器。诊断附着在现有启动器上，模块启动回滚后仍可检查此前的日志。

## 场景操作

将场景加入 Build Settings，在启动配置启用「场景模块」。默认宿主启动后，可从 `launcher.Modules` 取得 `SceneModule`。

```csharp
await launcher.Ready;
SceneModule scenes = launcher.Modules.Require<SceneModule>();
await scenes.SwitchAsync("Game", cancellationToken);
SceneHandle weather = await scenes.LoadAdditiveAsync("Weather", cancellationToken);
await scenes.UnloadAsync(weather, cancellationToken);
```

在主场景切换前，可以传入 `prepare` 完成关卡数据准备。使用 `SceneHandle.LoadAssetAsync<T>()` 加载的资源随场景管理。若在准备期间创建对象，将它放在目标场景的节点下，或使用 `SceneManager.MoveGameObjectToScene` 把已创建的根对象移入 `SceneHandle.Scene`。此前 Unity 的默认实例化目标仍是原活动场景。 [Unity 活动场景](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/SceneManagement.SceneManager.SetActiveScene.html) · [移动场景对象](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/SceneManagement.SceneManager.MoveGameObjectToScene.html)

`SwitchAsync` 成功后，目标已成为活动主场景，先前主场景已完成卸载。独立叠加层使用原句柄单独卸载。在准备和状态通知回调返回后，可以发起下一次场景操作。

项目界面可从 `scenes.State` 读取初始状态，再订阅 `scenes.Changed` 更新显示。停用或销毁界面时解除订阅。场景取消、失败与资源归还见 [Scene](模块职责/Scene.md)。
