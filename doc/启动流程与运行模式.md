# 自定义流程、运行环境与全局 Loading

## 设计边界

框架只提供 `ProcedureBase`、`ProcedureContext` 和 `ProcedureModule`，不再内置 Startup、Resource、HotUpdate、Preload、Login、Game、Exit 等具体业务流程。

具体流程必须写在项目程序集里。这样流程可以直接引用项目自己创建的 `LoginView`、角色脚本、服务和配置，不会受到“框架程序集不能反向引用项目程序集”的限制。

## 定义项目流程

项目可以继承 `ProcedureContext` 保存一条流程共享的业务状态：

```csharp
public sealed class GameProcedureContext : ProcedureContext
{
    public LoginView LoginView { get; set; }
    public PlayerService PlayerService { get; }

    public GameProcedureContext(PlayerService playerService)
    {
        PlayerService = playerService;
    }

    protected override void OnDispose()
    {
        if (LoginView != null)
            UIService.Close(LoginView);
    }
}
```

具体流程同样放在项目程序集里，因此可以直接使用项目类型：

```csharp
public sealed class LoginProcedure : ProcedureBase
{
    protected override async Task<Type> OnEnterAsync(CancellationToken cancellationToken)
    {
        GameProcedureContext context = RequireContext<GameProcedureContext>();
        context.LoginView = await UIService.OpenAsync<LoginView>();
        cancellationToken.ThrowIfCancellationRequested();
        return Stay();
    }

    protected override Task OnExitAsync(CancellationToken cancellationToken)
    {
        GameProcedureContext context = RequireContext<GameProcedureContext>();
        if (context.LoginView != null)
            UIService.Close(context.LoginView);
        context.LoginView = null;
        return Task.CompletedTask;
    }
}
```

返回 `Next<TProcedure>()` 会自动注册并进入下一流程；返回 `Stay()` 则停留，等待业务代码调用 `ChangeAsync<TProcedure>()`。`StartAsync` 和 `ChangeAsync` 遇到尚未注册的流程也会自动注册。

自动注册要求流程提供公开无参构造函数。需要构造参数或依赖注入时，仍可提前注册实例：

```csharp
procedures.Register(new LoginProcedure(loginService));
```

## 可选的依赖注入与启动

只有流程需要构造参数时，才通过业务 Registrar 提前注册对应实例：

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
private static void RegisterProcedures()
{
    ModuleRegistry.AddRegistrar(modules =>
    {
        ProcedureModule procedures = modules.Register<ProcedureModule>();
        procedures.Register(new LoginProcedure(loginService)); // 仅有构造参数时需要
    });
}
```

再从项目入口启动第一条流程：

```csharp
private async void Start()
{
    var context = new GameProcedureContext(new PlayerService());
    await ProcedureModule.Instance.StartAsync<ProjectStartupProcedure>(context);
}
```

## 启动配置

`FrameworkStartupConfig` 负责框架级运行环境、显示基础设施和首个流程入口。主要配置包括：

- 启动流程脚本：可直接选择项目中继承 `ProcedureBase` 的脚本。
- Runtime Mode。
- 是否启动 UI、渲染模式、相机、EventSystem 和 UI Layer。
- UI 与 Loading 共用的参考分辨率和宽高匹配值。
- UI 共享背景。
- Loading Prefab 和排序值。

配置了启动流程脚本后，Launcher 会自动创建 `ProcedureModule`，并在 UI 与 Loading 配置应用后使用基础 `ProcedureContext` 启动它。首流程以及后续通过 `Next` 或 `Change` 进入的流程都会按需自动注册。

如果首流程需要自定义 `ProcedureContext`，请把启动流程脚本留空，并从项目入口手动调用 `StartAsync`。IL2CPP 项目应给仅通过配置引用的首流程添加 `[UnityEngine.Scripting.Preserve]`。

## 运行环境

配置的 Runtime Mode 会在模块初始化前写入 `Runtime.Mode`：

- Editor：编辑器开发环境。
- Online：在线运行环境。
- Offline：本地或单机运行环境。
- Web：Web 运行环境。

项目可根据运行环境注入自己的资源 Loader：

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
private static void ConfigureResources()
{
    ModuleRegistry.AddRegistrar(modules =>
    {
        AssetModule assets = modules.Register<AssetModule>();
        assets.SetLoader(CreateLoader(Runtime.Mode));
    });
}
```

## 全局 Loading

Loading Prefab 为空时不创建 Loading；框架不会再隐式加载 `Resources/LoadingView.prefab`。Loading 使用独立 Overlay Canvas，但其参考分辨率、宽高匹配值和 Layer 与 UI 共用启动配置中的同一份配置。

```csharp
await LoadingModule.Instance.LoadSceneAsync("Game");

await LoadingModule.Instance.RunAsync(
    "正在加载数据",
    async progress =>
    {
        await LoadGameDataAsync(progress);
    });
```
