# EasyFramework 使用说明

EasyFramework 是一个轻量 Unity 游戏框架。默认装配事件、定时器、对象池、Tween、[音频](模块职责/Audio.md)和 [场景模块](模块职责/Scene.md)。资源、首流程和热更由启动配置决定，网络模块可按需装配。

## 一、启动

将框架放在 `Assets/` 下，在入口场景挂载 `FrameworkLauncher` 并赋给它一份 Startup Config。调用方绑定对应 Launcher，等待这个宿主就绪后使用模块。

```csharp
public class MyGame : MonoBehaviour
{
    [SerializeField] private FrameworkLauncher _launcher;

    private async void Start()
    {
        await _launcher.Ready;
        _launcher.Modules.Require<TimerModule>().Delay(2f, () => Log.Info("2 秒后执行"));
    }
}
```

默认启动配置会创建持久化的 `[UI]`、独立 UI Camera、Screen Space - Camera Canvas 和
EventSystem。通过 `Assets/Create/EasyFramework/Startup Config` 创建配置并赋给 Launcher。配置可切换
Overlay/Camera 模式、指定相机、UI Layer、相机深度、Canvas Scaler 和共享背景。

## 二、模块注册与生命周期

模块继承 `Module<T>`。项目装配器继承 `FrameworkModuleInstaller`，创建后加入启动配置的装配器列表。以下示例让项目的 `SaveModule` 等待 `AssetModule` 就绪。

```csharp
[CreateAssetMenu(menuName = "Game/Module Installer")]
public sealed class GameModuleInstaller : FrameworkModuleInstaller
{
    public override void Configure(ModuleComposition composition)
    {
        composition.Add<SaveModule>(typeof(AssetModule));
        composition.Add<NetworkModule>(_ => new NetworkModule(new TcpNetClient()));
    }
}
```

完整模块图通过依赖校验后，框架按阶段调用 `OnInit` 和 `OnInitAsync`。只有实现了 `IFrameUpdate` 的就绪模块参与帧更新。初始化失败时，框架等待在途任务收尾，再按初始化进入顺序的反向关闭。模块内部通过 `Host.Require<T>()` 取用依赖。

后续示例中的 `Module<T>.Instance` 使用当前作用域或默认宿主。隔离宿主的调用方可以通过 `launcher.Modules.Require<T>()` 明确获取模块。更多用法见 [Core](模块职责/Core.md) 和 [启动流程与运行模式](启动流程与运行模式.md)。

## 三、基础模块

### EventModule

```csharp
public struct PlayerDieEvent : IEvent
{
    public int PlayerId;
}

EventModule events = launcher.Modules.Require<EventModule>();
using var subscription = events.Subscribe<PlayerDieEvent>(evt => Log.Info($"player {evt.PlayerId} died"));
events.Dispatch(new PlayerDieEvent { PlayerId = 1 });
```

需要跨帧订阅时，将句柄保存在订阅对象中，并在对应的 `OnDisable` 或 `OnDestroy` 调用 `Dispose`。派发过程中释放尚未调用的订阅时，本次派发会跳过该回调。

### TimerModule

```csharp
TimerModule timer = launcher.Modules.Require<TimerModule>();
int once = timer.Delay(3f, () => Log.Info("3 秒游戏时间后执行"));
int loop = timer.Loop(1f, () => Log.Info("每秒执行"), TimerTimeMode.Unscaled);

timer.Cancel(loop);
```

计时任务默认使用缩放时间。宿主继续驱动帧循环时，非缩放任务可在 `Time.timeScale = 0` 时照常推进。

### PoolModule

```csharp
public sealed class Bullet : IPoolable
{
    public void OnSpawn() { }
    public void OnDespawn() { }
}

var bullet = PoolModule.Instance.Spawn<Bullet>();
PoolModule.Instance.Despawn(bullet);
```

同类型需要多个池时使用命名池：

```csharp
var redPool = PoolModule.Instance.GetOrCreate(
    "red",
    () => new Bullet(),
    maxSize: 64,
    onDestroy: bullet => { });

var red = redPool.Get();
PoolModule.Instance.Despawn("red", red);
```

默认开启归属和重复回收检查。`Prewarm` 按空闲容量预建对象，归还时已达到空闲容量的对象会触发 `onDestroy`。`ClearAll` 只清空闲对象，宿主关闭则清理所有仍由池持有的对象。 [对象池生命周期](模块职责/Pool.md)

## 四、可选模块

### NetworkModule

在模块安装器中为每个宿主注册一份独立传输。使用 TCP 时可写为
`composition.Add<NetworkModule>(_ => new NetworkModule(new TcpNetClient()));`。

```csharp
await launcher.Ready;
NetworkModule network = launcher.Modules.Require<NetworkModule>();
if (await network.ConnectAsync("127.0.0.1", 9000, cancellationToken))
{
    await network.SendAsync(1001, payload, cancellationToken);
}
```

默认 TCP 接收队列的消息预算为 4096，网络模块每帧最多读取 256 个事件，可通过 `MaxPendingEvents` 和 `MaxEventsPerUpdate` 调整。连接、断开和消息回调在宿主帧循环中派发，订阅者应在对应生命周期解除订阅。

`Send` 可直接提交发送。需要确认结果或传递取消令牌时，使用 `SendAsync`。替换传输及 TCP 分帧参见 [网络模块](模块职责/Network.md)。

### AssetModule

`Framework Startup Config` 配置资源包后会自动注册模块。第一次读取某个包时初始化其 Loader。单项资源用租约持有：

```csharp
using (var lease = await AssetModule.Instance.AcquireAsync<GameObject>("combat:Prefabs/Bullet", cancellationToken))
{
    GameObject prefab = lease.Asset;
}
```

页面或玩法可以用 `CreateScope()` 持有多项资源，关闭后统一取消等待和归还。最后一个租约归还时，模块根据缓存预算决定暂留或释放。包配置、内存和小游戏接入参见 [资源模块](模块职责/Asset.md)。

### 热更启动

YooAsset + HybridCLR 组合通过 Startup Config 关联热更发行，固定清单版本并按顺序准备资源、AOT 元数据、DLL 和入口。等待 `launcher.HotUpdateReady` 后即可访问受管资源或调用热更功能。两套 SDK 的引用由可选适配程序集承接。 [配置与运行说明](模块职责/Hotfix.md)

## 五、日志与工具

Development Build 的设备屏幕左上角会显示可拖动的 `DEBUGGER` FPS 悬浮框。
点击后可在 Console 页按 Info、Warning、Error、Fatal 筛选日志，锁定滚动、搜索、复制日志并查看堆栈。
Information 页提供 System、Environment、Screen、Graphics 信息；Profiler 页提供帧率、内存和场景信息；
Other 页可调整窗口布局，清空或复制日志，并执行垃圾回收和未使用资源卸载。
`FrameworkStartupConfig` 的“真机调试窗口”可设为 `DevelopmentBuild`（默认）、`Always`
或 `Disabled`。正式包需要调试时设为 `Always`；没有场景 Launcher 时请将配置保存为
`Resources/FrameworkStartupConfig.asset`。窗口不依赖 EventSystem 或业务 UI。

```csharp
Log.MinLevel = LogLevel.Info;
Log.Info("hello");
Log.Warn("warning");
Log.Error("error");

list.IsNullOrEmpty();
list.Shuffle();
dict.GetOrAdd(key, _ => new Value());
string value = input.Or("default");
int id = IdGenerator.Next();
```

自定义 `Log.Handler` 抛出的异常会被日志层吞掉，避免日志系统破坏游戏主循环。

## 六、自定义流程、运行环境与场景

项目在模块装配器中添加 `ProcedureModule`，登记每条流程的实例或工厂。运行时等待宿主就绪，再从所属宿主获取流程模块。

```csharp
await launcher.Ready;
ProcedureModule procedures = launcher.Modules.Require<ProcedureModule>();
await procedures.StartAsync<LoginProcedure>(new GameProcedureContext(playerService));
await procedures.ChangeAsync<GameProcedure>();
```

`StartAsync`、`ChangeAsync` 和 `Next<TProcedure>()` 的目标都要先登记。流程工厂可捕获模块装配时已就绪的依赖。首流程和上下文配置见 [Procedure](模块职责/Procedure.md)。

运行环境分为 Editor、Online、Offline、Web，并在模块初始化前写入 `Runtime.Mode`，供项目选择资源 Loader。

在启动配置启用「场景模块」，并在 Build Settings 启用目标场景。场景切换和叠加由 `SceneModule` 管理。

```csharp
await launcher.Ready;
SceneModule scenes = launcher.Modules.Require<SceneModule>();
await scenes.SwitchAsync("Game", cancellationToken);
SceneHandle extra = await scenes.LoadAdditiveAsync("Weather", cancellationToken);
await scenes.UnloadAsync(extra, cancellationToken);
```

场景作用域随卸载归还资源租约。项目界面可通过 `SceneModule.State` 和 `Changed` 展示场景操作的状态和进度。完整说明见 [场景操作](启动流程与运行模式.md#场景操作)。
