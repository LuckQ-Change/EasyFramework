# EasyFramework 使用说明

EasyFramework 是一个轻量 Unity 游戏框架。默认只注册事件、定时器和对象池；流程、全局 Loading、资源、热更与网络模块均由项目按需注册，资源和热更的具体 Loader 仍由项目注入。

## 一、启动

将框架放在 `Assets/` 下后，会在首个场景加载前自动创建 `[EasyFramework]` 对象并启动框架：

```csharp
public class MyGame : MonoBehaviour
{
    private void Start()
    {
        TimerModule.Instance.Delay(2f, () => Log.Info("2 秒后执行"));
    }
}
```

如需关闭自动启动，添加 `EASY_NO_AUTO_BOOTSTRAP`，并在场景中手动挂载 `FrameworkLauncher`。静态状态重置不受该宏影响，关闭 Domain Reload 时也不会累积旧注册器。

默认启动配置会创建持久化的 `[UI]`、独立 UI Camera、Screen Space - Camera Canvas 和
EventSystem。通过 `Assets/Create/EasyFramework/Startup Config` 可创建自定义配置；手动 Launcher
直接引用该资产，自动 Launcher 则读取 `Resources/FrameworkStartupConfig.asset`。配置可切换
Overlay/Camera 模式、指定相机、UI Layer、相机深度、Canvas Scaler 和共享背景。

## 二、模块注册与生命周期

模块继承 `ModuleSingleton<T>`，通过 `ModuleRegistry` 注册：

```csharp
public sealed class SaveModule : ModuleSingleton<SaveModule>
{
    protected override void OnInit() { }
    protected override void OnUpdate(float deltaTime) { }
    protected override void OnShutdown() { }
}

public static class GameModuleBootstrap
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    private static void Register()
    {
        ModuleRegistry.AddRegistrar(modules =>
        {
            modules.Register<SaveModule>();
            modules.Register<NetworkModule>(); // 按需
        });
    }
}
```

生命周期约定：

1. 收集并注册全部模块，此时所有 `Instance` 已就位。
2. 按注册顺序调用 `OnInit`。
3. 每帧按注册顺序调用 `OnUpdate`。
4. 关闭时逆序调用 `OnShutdown`。

初始化失败时，已进入初始化流程的模块会被逆序回滚，所有单例引用会清空。单个模块更新或关闭异常不会阻断其他模块。

业务 registrar 和自动启动的执行先后不确定，但 registrar 如果晚到，会作为一个完整批次安装：先注册该批次的全部模块，再逐个初始化。因此不会静默漏注册。

不要直接 `new XxxModule()`。直接创建的对象不归 `ModuleManager` 管理，也不会成为 `XxxModule.Instance`。

## 三、基础模块

### EventModule

```csharp
public struct PlayerDieEvent : IEvent
{
    public int PlayerId;
}

Action<PlayerDieEvent> handler = evt => Log.Info($"player {evt.PlayerId} died");
EventModule.Instance.Subscribe(handler);
EventModule.Instance.Dispatch(new PlayerDieEvent { PlayerId = 1 });
EventModule.Instance.Unsubscribe(handler);
```

事件处理器相互隔离。派发过程中退订尚未调用的处理器，该处理器不会在本次派发中继续执行。匿名 lambda 如需退订，必须保存委托引用。

### TimerModule

```csharp
int once = TimerModule.Instance.Delay(3f, () => Log.Info("once"));
int loop = TimerModule.Instance.Loop(1f, () => Log.Info("loop"));

TimerModule.Instance.Cancel(loop);
TimerModule.Instance.CancelAll();
```

计时器使用 `Time.deltaTime`。在计时器回调内创建并立即取消的新计时器也能正确取消。

### PoolModule

```csharp
public sealed class Bullet : IPoolable
{
    public void OnSpawn() { }
    public void OnDespawn() { }
}

var bullet = PoolModule.Instance.Spawn<Bullet>();
PoolModule.Instance.Despawn(bullet);
```

同类型需要多个池时使用命名池：

```csharp
var redPool = PoolModule.Instance.GetOrCreate(
    "red",
    () => new Bullet(),
    maxSize: 64,
    onDestroy: bullet => { });

var red = redPool.Get();
PoolModule.Instance.Despawn("red", red);
```

开发期默认开启归属和重复回收检查。`Prewarm` 不会超过容量，超出容量的回收对象会触发 `onDestroy`。

## 四、可选模块

### NetworkModule

先在 registrar 中注册 `NetworkModule`，然后使用：

```csharp
NetworkModule.Instance.OnConnected += () => Log.Info("connected");
NetworkModule.Instance.OnDisconnected += reason => Log.Warn(reason);
NetworkModule.Instance.OnMessage += message => Log.Info($"recv {message.MsgId}");

await NetworkModule.Instance.ConnectAsync("127.0.0.1", 9000);
bool sent = await NetworkModule.Instance.SendAsync(1001, payload, cancellationToken);
```

协议帧为 `[4 字节大端 body 长度][4 字节大端 MsgId][payload]`。回调在 Unity 主线程派发。默认接收队列上限为 4096，每帧最多派发 256 个事件，可通过 `MaxPendingEvents` 和 `MaxEventsPerUpdate` 调整。

`Send` 保留为无需等待的便捷 API，但需要确认结果、超时或取消时应使用 `SendAsync`。心跳、自动重连和序列化协议由业务扩展，不放入基础传输层。

### AssetModule

`AssetModule` 已默认注册，项目只需在模块初始化阶段设置 Loader：

```csharp
var memory = new MemoryAssetLoader();
memory.Add("Prefabs/Bullet", prefab);

AssetModule.Instance.SetLoader(memory);
await AssetModule.Instance.InitializeAsync();
```

推荐使用租约明确资源所有权：

```csharp
using (var lease = await AssetModule.Instance.AcquireAsync<GameObject>("Prefabs/Bullet"))
{
    GameObject prefab = lease.Asset;
}
```

相同 location 的并发加载会合并，最后一个租约释放时才调用 Loader 的 `Release`。兼容 API `LoadAsync<T>` 仍可使用，但必须成对调用 `Release(location)`。

安装 YooAsset 后，给 Runtime asmdef 添加 YooAsset 程序集引用并定义 `EASY_YOOASSET`，然后设置 `YooAssetLoader`。Loader 初始化完成后禁止热替换；需要更换时应先关闭并重新初始化框架。

### HotfixModule

`HotfixModule` 已默认注册并可使用默认 Assembly Loader。安装 HybridCLR 后，给 Runtime asmdef 添加 HybridCLR 程序集引用并定义 `EASY_HYBRIDCLR`：

```csharp
HotfixModule.Instance.SetLoader(new HybridCLRLoader());
HotfixModule.Instance.LoadAotMetadata(aotDllBytes);
var assembly = HotfixModule.Instance.LoadHotfix(hotfixDllBytes);
HotfixModule.Instance.InvokeEntry(assembly, "HotUpdate.GameMain", "Start");
```

## 五、日志与工具

```csharp
Log.MinLevel = LogLevel.Info;
Log.Info("hello");
Log.Warn("warning");
Log.Error("error");

list.IsNullOrEmpty();
list.Shuffle();
dict.GetOrAdd(key, _ => new Value());
string value = input.Or("default");
int id = IdGenerator.Next();
```

自定义 `Log.Handler` 抛出的异常会被日志层吞掉，避免日志系统破坏游戏主循环。

## 六、自定义流程、运行环境与 Loading

框架只提供流程基础设施，不内置具体的启动、登录、游戏或退出流程。业务流程放在项目程序集后，可以直接访问项目自己的 UI 和脚本：

```csharp
ProcedureModule procedures = ProcedureModule.Instance;
await procedures.StartAsync<LoginProcedure>(new GameProcedureContext());
await procedures.ChangeAsync<GameProcedure>();
```

`StartAsync`、`ChangeAsync` 与流程返回的 `Next<TProcedure>()` 都会按需自动注册无参流程；只有需要构造参数时才要提前注册流程实例。

运行环境分为 Editor、Online、Offline、Web，并在模块初始化前写入 `Runtime.Mode`，供项目选择资源 Loader。

场景加载统一使用全局 Loading：

```csharp
await LoadingModule.Instance.LoadSceneAsync("Game");
```

Loading Prefab 需要在启动配置中显式指定；UI 与 Loading 共用同一套屏幕适配参数。完整说明见 [自定义流程、运行环境与全局 Loading](启动流程与运行模式.md)。
