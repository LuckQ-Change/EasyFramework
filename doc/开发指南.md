# EasyFramework 开发指南

## 项目定位

- 包名：`com.wjq.easyframework`
- Unity：2022.3 LTS
- 形态：核心 Runtime 加可选适配程序集
- 原则：确定的生命周期、按需注册、明确所有权、主循环低分配

框架刻意不内置具体业务流程、存档、完整网络协议栈或大型依赖注入容器。流程模块只负责注册和切换项目定义的流程；资源和热更只提供适配入口，不重复实现 YooAsset、HybridCLR 已解决的问题。

## 编码规范

### 1. 命名与 Inspector 序列化

- 类、结构体、枚举、公共方法和公共属性用 `PascalCase`。私有字段用 `_camelCase`，局部变量和参数用 `camelCase`，常量用 `UPPER_SNAKE_CASE`。
- 布尔变量和属性以 `is`、`has`、`can` 开头，并遵守各自的大小写规则，例如 `_isGrounded`、`hasTarget`、`CanDash`。
- Inspector 与依赖绑定优先走项目现有框架的绑定、注入或面板特性。仅需手动配置时使用 `[SerializeField] private Type _fieldName;`，酌情使用 `[Header]` 或 `[Tooltip]`。字段的可见性由代码调用需求决定。
- EasyFramework 业务预设按工程配置使用 `关键字_属性名` 命名绑定节点，由框架自动扫描生成绑定。嵌套业务视图使用 `node_` 绑定，各自扫描内部控件。GFProject 的生成脚本统一放在 `Assets/GameMain/Runtime/Generated/`。

### 2. 中文注释与代码组织

- 所有类、接口、枚举以及公共方法和公共属性都使用中文 XML `<summary>` 说明职责。有参数或返回值时，用 `<param>` 和 `<returns>` 描述实际含义。
- 在状态切换、向量或四元数计算、射线检测等关键逻辑上方，用中文 `//` 说明设计意图和约束。
- 超过 150 行的脚本按 `#region 生命周期`、`#region 公共方法`、`#region 私有逻辑` 组织适用的代码段。

### 3. 性能、物理和生命周期

- `Update()`、`FixedUpdate()`、`LateUpdate()` 保持零 GC 分配。严禁在其中调用 `GetComponent()`、`Camera.main`、`FindObjectOfType()`、创建 `List` / `Dictionary` 或用 `+` 拼接字符串。组件引用在初始化阶段缓存，高频生成的子弹、特效和伤害飘字走对象池。
- 输入采样在 `Update()`，`Rigidbody` 或 `Rigidbody2D` 的移动与施力在 `FixedUpdate()`。
- C# 事件、框架事件总线、输入回调等订阅必须在 `OnDisable()` 或 `OnDestroy()` 成对解除，并与订阅时机匹配。跨对象调用前和获取组件后先判空。

## 核心不变量

### 模块生命周期

- 新宿主先通过 `ModuleComposition` 声明工厂和必需依赖。完整依赖图通过检查后才创建模块，依赖就绪后才初始化使用方。
- 每个宿主独立持有模块。模块间调用使用 `Host`，场景入口通过绑定的 `FrameworkLauncher.Modules` 取用。作用域查询使用当前宿主或显式指定的默认宿主。
- 初始化失败时先取消并等待在途初始化结束，再逆序关闭已经进入初始化的模块，清除失败批次。
- 显式装配的根模块图启动后固定。
- 更新和关闭错误必须隔离，不能阻断其他模块。
- 同阶段的异步初始化可以重叠。只有实现 `IFrameUpdate` 的就绪模块才参与 Tick，按初始化的启动顺序更新。

### 所有权

- 池对象只能回收到创建它的池，重复回收视为错误。
- 通过 `AssetLease<T>` 或 `AssetScope` 持有资源。最后一个租约归还后由空闲缓存策略决定底层释放时机。实例、池中对象和仍在使用的组件引用都需要保留所属租约。
- TCP 接收任务只允许清理自己的连接上下文，旧连接不能影响新连接。

### 可选能力

内置默认模块为 Event、Timer、Pool、Tween 和 Audio，Startup Config 还默认启用 SceneModule。资源模块按资源配置装配。流程模块、首流程和其他项目模块由装配器登记。

## 扩展模块规范

```csharp
public sealed class ExampleModule : Module<ExampleModule>, IFrameUpdate
{
    protected override void OnInit()
    {
        // 获取依赖、订阅事件；失败可抛异常触发启动回滚。
    }

    void IFrameUpdate.Tick(FrameTime frameTime)
    {
        // 根据需要读取 ScaledDeltaTime 或 UnscaledDeltaTime，避免每帧分配。
    }

    protected override void OnShutdown()
    {
        // 必须幂等，释放订阅、句柄和后台任务。
    }
}
```

模块构造函数只做字段初始化，不启动任务、不访问 Unity 场景、不持有外部资源。同步初始化放在 `OnInit`，异步初始化放在 `OnInitAsync`，释放放在 `OnShutdown`。

## 隔离验证

在工程外的独立副本验证改动，以下场景可用作回归范围。

- Core：初始化顺序、失败回滚、逆序关闭、晚到安装。
- Event：订阅变更、嵌套派发、处理器异常隔离。
- Pool：重复/外来回收、容量、清理与销毁回调。
- Timer：回调内新增、取消和异常处理。
- Tween：手动推进、时间模式、Sequence 顺序与并行、中断和所有权释放。
- Asset：并发加载合并、引用计数、关闭期间完成加载。
- Network：分帧、半包、坏帧、断开重连和发送顺序。

## 发布检查

1. Runtime 在未定义第三方宏时通过编译。
2. 分别安装目标版本 YooAsset、HybridCLR，启用宏验证适配器。
3. 隔离工程中的相关回归通过。
4. 检查 `README.md`、`CHANGELOG.md`、使用文档和 `package.json` 版本一致。
5. 在 Mono 与 IL2CPP Development Build 各做一次最小启动验证。
