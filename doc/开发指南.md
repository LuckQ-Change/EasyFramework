# EasyFramework 开发指南

## 一、项目识别

**项目名称**：EasyFramework（com.qchanger.easyframework）
**项目类型**：Unity Package（UPM 格式自定义包）
**Unity 版本**：2022.3.0b5
**作者**：WJQ
**项目定位**：一款简易的 Unity 游戏框架，包含热更新、资源管理、网络通信、事件系统、对象池、工具集等核心模块（UI 模块暂未实现）。

### 项目结构

```
EasyFramework/
├── package.json                                        # UPM 包描述文件
├── Editor/                                             # 编辑器扩展（程序集）
│   └── com.wjq.easyframework.editor.asmdef
├── Runtime/                                            # 运行时代码（程序集）
│   ├── com.wjq.easyframework.runtime.asmdef
│   ├── Core/                                           # 框架核心（入口、模块管理、生命周期）
│   ├── Event/                                          # 事件系统
│   ├── HybridCLR/                                      # 热更新（基于 HybridCLR）
│   ├── NetWork/                                        # 网络模块
│   ├── Pool/                                           # 对象池
│   ├── Utils/                                          # 通用工具
│   ├── YooAsset/                                       # 资源管理（基于 YooAsset）
│   └── Bootstrap/                                      # Unity 启动器
└── doc/                                                # 文档目录
```

## 二、需要学习的技术栈

### 2.1 基础技术
| 技术                       | 用途                          | 学习重点                                  |
| -------------------------- | ----------------------------- | ----------------------------------------- |
| **C# (.NET / Mono)**       | 框架主语言                    | 泛型、委托/事件、async/await、反射、特性  |
| **Unity 2022.3 LTS**       | 引擎                          | MonoBehaviour 生命周期、协程、ScriptableObject、Editor 扩展 |
| **Unity Package Manager**  | 包分发                        | asmdef 程序集定义、package.json 规范、版本与依赖 |
| **UniTask**（推荐）        | 异步编程                      | 替代协程 / Task，零 GC 的异步流程         |

### 2.2 核心模块技术
| 模块          | 推荐技术 / 第三方库                  | 说明                                                   |
| ------------- | ------------------------------------ | ------------------------------------------------------ |
| **Core**      | 单例、模块化设计、IoC 思想           | 框架入口、模块注册与生命周期驱动                       |
| **Event**     | C# 委托、订阅/发布模式               | 类型安全的事件总线、对象池化事件参数                   |
| **HybridCLR** | [HybridCLR](https://hybridclr.doc.code-philosophy.com/) | 阿里推出的 IL2CPP 全特性热更方案                     |
| **NetWork**   | TCP / KCP / WebSocket、Protobuf      | 长连接通信、消息序列化、心跳与断线重连                 |
| **Pool**      | Stack/Queue 池、IObjectPool<T>       | GameObject 池、C# 对象池、纹理与资源池                 |
| **Utils**     | 日志、定时器、单例、扩展方法         | 通用工具集                                             |
| **YooAsset**  | [YooAsset](https://www.yooasset.com/)| 资源管理、AB 包构建与寻址、版本更新                    |

### 2.3 进阶辅助
- **设计模式**：单例、工厂、观察者、状态机、命令模式
- **序列化**：JSON.NET / MemoryPack / Protobuf-net
- **日志系统**：自定义 Logger，分级输出、文件落地
- **构建管线**：Unity Build Pipeline、Addressables 对比 YooAsset
- **Git / GitHub**：版本控制、分支策略、PR 流程

## 三、推荐开发步骤

### 阶段 0：环境准备
1. 安装 Unity 2022.3.0b5（与 `package.json` 中 `unity` 字段一致）。
2. 安装 Rider 或 Visual Studio 2022（带 Unity 工作负载）。
3. 配置 Git，并将 `EasyFramework` 作为子模块或独立仓库管理。
4. 创建一个 Demo 工程，通过 UPM 引入本框架（本地路径 / Git URL）。

### 阶段 1：Core 核心层（最先做，所有模块依赖它）
1. 设计 **框架入口 `EasyFramework.cs`**：提供 `Init / Update / Shutdown` 生命周期。
2. 实现 **泛型单例基类**（MonoSingleton、Singleton）。
3. 设计 **模块接口 `IModule`** 与 **模块管理器 `ModuleManager`**：所有模块注册到此处统一驱动。
4. 实现 **日志系统**（Utils/Logger）：支持 Debug/Info/Warn/Error 分级、TAG、是否打印堆栈。
5. 编写简单的 **示例场景** 验证框架启动流程。

### 阶段 2：Utils 工具层
1. **协程/UniTask 包装**：定时器（Timer）、延时调用（DelayCall）。
2. **扩展方法**：Transform、string、collection 等。
3. **数学辅助 / 加密 / 文件 IO**。
4. **单元测试**（Unity Test Framework）保证基础工具稳定。

### 阶段 3：Event 事件系统
1. 定义事件基类 `IEvent` 或泛型 `Event<T>`。
2. 实现 **EventManager**：`Subscribe / Unsubscribe / Dispatch`，支持优先级与一次性订阅。
3. 引入 **事件参数对象池**（衔接 Pool 模块）。
4. 单元测试覆盖订阅 / 注销 / 异常隔离。

### 阶段 4：Pool 对象池
1. **C# 对象池**：`ObjectPool<T> where T : class, new()`。
2. **GameObject 池**：按 prefab 分桶管理；提供 `Spawn / Despawn / Prewarm / Clear`。
3. 与 YooAsset 整合：异步加载 prefab → 入池。
4. 编辑器 GUI：池状态监控窗口（命中率、容量）。

### 阶段 5：YooAsset 资源模块
1. 通过 UPM 安装 YooAsset 包。
2. **AssetManager** 封装：初始化（编辑器 / 离线 / 联机三种运行模式）、同步/异步加载、句柄释放、引用计数。
3. AB 包构建脚本与命名规则。
4. 提供 **资源更新流程**：清单下载 → 差异比对 → 增量下载 → 解压验证。

### 阶段 6：HybridCLR 热更模块
1. 安装 HybridCLR 包并执行 Installer。
2. 划分 **AOT 程序集** 与 **热更程序集**，配置 link.xml 与 AOT 元数据补充。
3. 将热更 DLL 作为资源由 **YooAsset** 下发。
4. 启动时由 Core 加载并 `Assembly.Load`，反射调用热更入口。
5. 编辑器流程演练：发布 → 改代码 → 热更下发 → 客户端生效。

### 阶段 7：NetWork 网络模块
1. 协议层：选定传输方式（TCP / KCP / WebSocket）。
2. 序列化：推荐 **Protobuf**（protobuf-net 或 Google.Protobuf）。
3. 实现：连接管理、消息分包、心跳、断线重连、消息派发到 Event。
4. 编写 **回环测试服务**，验证收发与压力。

### 阶段 8：Editor 编辑器扩展
1. 框架配置面板（ScriptableObject + Custom Editor）。
2. AB 包打包工具、热更 DLL 打包工具。
3. 模块状态调试窗口（事件订阅、对象池状态）。

### 阶段 9：发布与维护
1. 完善 `package.json`（version、license、documentationUrl）。
2. 编写 README、CHANGELOG、API 文档（推荐 DocFX）。
3. 打 tag，按语义化版本（SemVer）发布。
4. 在示例项目中持续验证，收集反馈迭代。

## 四、模块依赖关系

```
                Core (入口 + 模块管理 + 日志)
                  │
        ┌─────────┼─────────┬──────────┐
        ▼         ▼         ▼          ▼
      Utils     Event      Pool      NetWork
                                       
                              YooAsset ──► HybridCLR
```

> 建议开发顺序：**Core → Utils → Event → Pool → YooAsset → HybridCLR → NetWork → Editor**。
