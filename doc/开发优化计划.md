# EasyFramework 开发优化计划

## 目标与边界

EasyFramework 的整体目标是让模块边界、生命周期和错误处理清晰可验收。UI 保留 UGUI Prefab 作为内容的唯一资产，保留 `UIService`、`UIDisplay` 和纯 C# `UIView` 的运行时模型。编辑工作在 Unity 内完成：Prefab Mode 和 Scene View 负责画布，统一的 UI 工作台负责页面、引用、状态、动画和校验。Tween 由框架 Runtime 实现，供业务代码、UI 转场和编辑器预览共同使用。

每个阶段必须完成“创建或配置 → 预览 → 保存 → 运行 → 修改或撤销 → 错误定位”的行为闭环。验收以可重复的操作和自动测试为准；未通过当前阶段的验收，不将下一阶段标为完成。

## 跨阶段约束

1. Prefab 中的组件引用和状态数据只有一个权威来源；编辑器不另存一份运行时副本。View 的资源地址继续以 `UIPrefab` 为准。
2. 每次编辑操作支持 Unity Undo，并在 Prefab Mode 中正确标记脏状态。预览结束后恢复原始外观，不把预览值写进 Prefab。
3. 页面关闭、对象销毁、切换状态或中断动画后，不保留悬挂回调、Tween、资源租约或输入遮挡。
4. 无效配置在编辑期给出可定位的错误；运行时仍做防御性检查。生成失败不得留下“Prefab 存在、脚本缺失”这类半成品。
5. 新增运行时行为有 EditMode 测试；需要 Unity 生命周期或可视化行为的部分增加 PlayMode 或人工验收步骤。发布前检查 2022.3、Mono 和 IL2CPP。
6. 该约束适用于整个框架。一个脚本只承担一个明确职责；插值计算、播放状态、调度、Sequence 编排、Unity 生命周期适配、编辑器展示分别放在独立类型中。公开函数只做与其命名一致的动作；状态变更和完成回调的语义在测试中固定。
7. 每个公开类型和有非显然行为的函数都用简短注释说明用途、输入约束和生命周期结果。注释解释“为什么”以及边界条件，避免仅把代码翻译成自然语言；接口、实现、测试和文档使用同一术语。

## 阶段 0：基线与制作路径

**任务**：记录现有 UI 创建、资源加载、引用、状态和转场的实际路径；修正文档中 AssetModule 默认注册的矛盾；给出一条从创建页面到打开页面的最小示例。

**验收**：新项目按文档配置 Loader 后，能创建页面、取得一个组件引用、切换一个状态并通过 `UIService` 打开与关闭；文档中的默认模块列表与 `ModuleRegistry` 一致。每个失败点都有明确的前置条件和处理方式。

## 阶段 1：Tween 内核

**任务**：实现可手动推进的 Tween 调度、常用数值插值、Ease、Sequence、缩放和非缩放时间、播放控制、目标生命周期绑定。运行时逐帧更新复用集合，不为每帧回调创建新委托。

**验收**：零时长、完成、中断、暂停、重播、嵌套创建、回调异常、目标销毁和框架关闭均有确定结果；完成回调恰好一次，中断不误触发完成回调；Sequence 的串行与并行终值正确；EditMode 测试能用手动 Tick 重现这些结果。代码评审可直接指出每个类型的唯一职责，新增动画属性不要求修改调度器。

## 阶段 2：UI 转场接入

**任务**：让 `UITransition` 使用 Tween 内核；保留现有淡入、淡出、缩放配置和 `UIManager` 调用入口。打开、关闭或重新打开时处理动画竞争，恢复对象原有缩放，明确输入阻挡与关闭完成时机。

**验收**：连续打开和关闭、淡入中关闭、淡出中再次打开、零时长、对象销毁均不出现残影、重复销毁、漏释放或永久遮挡；关闭完成回调仅执行一次；与无转场页面的栈、焦点和背景行为一致。

## 阶段 3：Unity 内的统一 UI 工作台

**任务**：将现有创建向导、Display 设置、引用、状态、校验和组件转换整合为一个可停靠入口；与 Project、Hierarchy、Scene View 和 Prefab Mode 的选择同步。画布仍编辑真实 UGUI Prefab，不建立额外 UI 资源格式。

**验收**：从工作台创建页面后可直接打开 Prefab；选择节点即可看到引用和状态；点击问题能定位对象；保存、撤销、重进 Prefab 后结果一致。至少用一个真实示例完成“创建 → 布局 → 引用 → 状态 → 预览 → 运行”全流程。

## 阶段 4：状态和引用的可视化闭环

**任务**：状态页切换后，受控属性在 Scene View 中修改时自动记录；提供变化标记、恢复默认和冲突提示。引用支持从节点一键暴露，并生成可编译的强类型访问入口或常量；重命名能检查业务使用点。

**验收**：两种状态互不覆盖；保存 Prefab 不泄漏当前预览外观；Undo/Redo 后状态数据与画布一致；修改引用 Key 后，生成代码和校验结果一致，缺失目标在编辑期报错。

## 阶段 5：适配、组件与动画时间轴

**任务**：添加分辨率和安全区预览、常用 Anchor/Layout 预设、可复用 UI Item 模板；基于同一 Tween 内核制作可拖动进度的 UI 时间轴。长列表虚拟化在示例确认需求后加入。

**验收**：切换预览分辨率不会修改 Prefab；时间轴任意位置 Seek 的画面与运行时一致，退出预览恢复原值；复制或复用 Item 不破坏引用作用域；列表示例能验证复用、滚动和资源释放。

## 阶段 6：全框架职责与注释审查

**任务**：逐模块审查 Bootstrap、Core、Event、Pool、Timer、Asset、Network、Hotfix、Loading、Procedure、UI 和 Tween。对职责混杂的类拆分，对同义或含糊的 API 命名统一，补齐关键生命周期和异常路径的注释。拆分保持现有公开行为，必要的兼容层单独标记和测试。

**验收**：每个模块有一页简明职责说明；代码评审能为每个公开类说出唯一的主职责及其依赖方向；一个公开方法只完成命名所描述的操作；所有权、失败回滚和关闭路径有测试；XML 注释与实际行为一致，未留下过时描述。

| 模块 | 职责边界 | 关键闭环验收 |
| --- | --- | --- |
| Bootstrap / Core | 配置与启动、模块注册与生命周期调度分开 | 启动失败逆序回滚；重复启动和关闭无残留单例 |
| Event / Timer / Pool | 分别处理派发、时间调度、对象复用 | 回调中增删安全；取消和重复回收行为确定 |
| Asset / Hotfix | 分别处理资源租约、程序集加载适配 | 初始化失败可恢复；最后一个租约释放资源；关闭不留句柄 |
| Network | 连接、收发帧、主线程事件派发分别有边界 | 半包、断连、重连、队列满和关闭均不串连接状态 |
| Loading / Procedure | 加载状态与展示分开；流程状态与业务流程分开 | 取消、失败和场景切换后 UI 与上下文正确收尾 |
| UI / Tween | 页面管理、显示配置、引用、状态、动画调度分开 | 打开、关闭、中断、预览、保存与资源释放结果一致 |

## 阶段 7：发布与回归

**任务**：补齐编辑器流程测试、样例 Prefab、使用说明和版本记录；运行 EditMode、必要的 PlayMode 与目标平台构建检查。

**验收**：上述闭环全部通过；样例在干净 Unity 2022.3 项目中可复现；无编译错误、缺失引用和未完成的资源地址；发布文档与实际默认配置一致。
